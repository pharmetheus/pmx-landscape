# Population PK software in FDA reviews of CDER novel approvals, 2021 to 2025

This package reproduces a survey of which population PK (popPK) software is named in FDA's published review documents for the 238 CDER novel drug approvals of 2021 to 2025. It records the software used by the sponsor (Applicant) separately from software used by FDA reviewers, and keeps PBPK and NCA tools apart from popPK estimation tools.

The package contains the final results, the decision rules, the scripts, and the extracted text of every searched page (text layer plus OCR). You can therefore re-run or change the search in a couple of minutes without downloading or OCR-ing anything. The PDFs themselves (3.2 GB) are not included; the scripts download them again from FDA if needed.

Data were retrieved in September 2026.

## Contents

```
README.md                  this file
docs/METHODS.md            sources, decision rules, categories, limitations, change history
results/
  fda_2021_2025_popPK_software.csv   one row per drug: the result and the evidence (links, page numbers)
  summary_sponsor_by_year.csv        counts by year (written by scripts/08_summarize.py)
config/
  patterns.json            the regular expressions used in the final search
  frame_overrides.json     application numbers not available as links on FDA's pages (4 drugs, 2025)
  doc_overrides.json       documents added by hand (Aduhelm fallback; Zurzuvae, now also found automatically)
  known_exceptions.json    pattern matches that are documented non-use (OCR noise, FDA template phrase)
scripts/
  common.py                shared helpers
  01_frame.py              list of novel approvals for a year, with application numbers
  02_retrieve.py           find (openFDA + Drugs@FDA) and download the review PDFs
  03_extract.py            text layer, page by page (pdftotext)
  04_ocr.py                OCR of image-only pages (pdftoppm + tesseract)
  05_search.py             regex search of every page -> data/<year>/hits.json
  06_context.py            show the text around a hit and nearby attribution labels (manual review aid)
  07_verify.py             compare a fresh search with the recorded results; lists anything unexplained
  08_summarize.py          count tables from the results CSV
data/<year>/               for 2021 to 2025
  frame.json               the novel approvals list for that year
  docs.json                review documents per application: type, FDA folder year, URL, text file
  txt/                     text layer of each document (pages separated by form feed characters)
  ocr/                     OCR text for image-only pages: <document>_p<page>.txt
  hits.json                output of 05_search.py (regenerated by the scripts)
```

## Requirements

Python 3.10 or later with `requests` and `beautifulsoup4`. For steps 3 and 4 only: poppler (`pdftotext`, `pdftoppm`) and tesseract 5 with English data.

Tested with Ubuntu 24.04, Python 3.12.3, requests 2.33.1, beautifulsoup4 4.14.3, poppler 24.02.0 and tesseract 5.3.4.

```
pip install requests beautifulsoup4
sudo apt install poppler-utils tesseract-ocr        # only needed to rebuild from PDFs
```

Run all scripts from the `scripts/` folder, for example `cd scripts; python 05_search.py all`.

## A. Check the results against the cached text (2 minutes, no internet)

```
python 05_search.py all      # regex search of all 238 drugs, writes data/<year>/hits.json
python 07_verify.py          # expected output: 0 unexplained software mentions
python 08_summarize.py       # count tables, writes results/summary_sponsor_by_year.csv
```

`07_verify.py` reports every software mention that the results CSV does not account for. With the shipped data and patterns it reports none.

## B. Change or add search terms

1. Edit `config/patterns.json` (Python regular expressions; each pattern has a group: estimation, auxiliary, pbpk, nca, other, marker).
2. Run `python 05_search.py all` and `python 07_verify.py`.
3. For every UNEXPLAINED line, read the context:
   `python 06_context.py 2024 216158 265 NONMEM`
   Decide who used the software and whether it is real use (rules in `docs/METHODS.md`). Then either correct the row in the results CSV or add the match to `config/known_exceptions.json` with a reason.
4. Run `07_verify.py` again until it reports zero, then `08_summarize.py`.

The search itself only finds mentions. The reading step in 3 is what turns a mention into a result, and it is the step where two readers could occasionally disagree.

## C. Rebuild a year from the FDA sources

```
python 01_frame.py 2024          # writes data/2024/frame.json (use --out to avoid overwriting)
python 02_retrieve.py 2024       # about 10 minutes per year; resumable
python 03_extract.py 2024
python 04_ocr.py 2024            # about 1 to 1.5 s per image-only page; 600 to 1,600 pages per year
python 05_search.py 2024
```

Then review the hits as in B. To rebuild into a clean copy, copy `scripts/` and `config/` to a new folder with an empty `data/` folder. FDA occasionally re-posts or re-redacts documents, so a rebuild can differ slightly from the shipped text.

Checked when building this package: `01_frame.py` reproduces the application numbers for 2021 and 2024 exactly; `02_retrieve.py` finds the documents for the special cases Cosela (filed in the 2020 folder), Aduhelm (fallback documents) and Zurzuvae (approved under Orig2); and `04_ocr.py` gives byte-identical OCR text to the shipped files.

## D. Extending to other years

The scripts take the year as an argument, so `01` to `05` can be run for 2016 to 2020. Expect more work than for 2021 to 2025: older reviews are more often scanned, clinical pharmacology is usually a standalone review, and some older table-of-contents pages lack the JavaScript variables that `02_retrieve.py` reads (it then falls back to the base name in the TOC URL). Check `data/<year>/retrieval_log.json` for drugs with notes, and add missing documents to `config/doc_overrides.json`. To include a new year in the results, add its rows to the results CSV after review.

## Results file: columns

| Column | Meaning |
|---|---|
| year, no, drug, application, approval_date | From FDA's novel approvals page (no = row number on that page) |
| review_docs, review_urls | Documents searched: type and FDA folder year, and their URLs |
| sponsor_tool_family | NONMEM, Monolix, Phoenix NLME or Pumas; empty if none identified |
| sponsor_popPK_software | Software and version as written in the review |
| evidence_strength | stated; indirect; or indirect, template phrase only (see METHODS) |
| sponsor_evidence_pages | How the evidence reads and where (PDF page index, 1-based; not the printed page number) |
| sponsor_auxiliary_tools | PsN, Pirana, Xpose, mrgsolve, RxODE, Simulx, MATLAB (QSP) and similar |
| fda_tool_family, fda_reviewer_software | Software the FDA reviewer states they used, with pages |
| pbpk_nca | PBPK (Simcyp, GastroPlus, PK-Sim) and NCA tools, kept separate from popPK |
| category | Tool stated; Tool stated (indirect); popPK present, software not stated; No popPK analysis in review |
| notes | Special handling for that drug |

## Headline numbers (from 08_summarize.py)

Of the 238 drugs, all have a posted review. A sponsor popPK tool is identifiable for 148: NONMEM 136 (92%), Monolix 8 (5%), Phoenix NLME 3 (2%), Pumas 1 (1%). For 63 drugs a popPK analysis is described without naming the software, and 27 reviews contain no popPK analysis. See `docs/METHODS.md` for how these were derived and their limitations.
